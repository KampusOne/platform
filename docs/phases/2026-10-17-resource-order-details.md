# Learning resource and order details

Learning resources now show a cover and real format/page/part metadata, a compact tutor identity row, an expandable description and preview, and a small Kira study panel. The tutor row opens the existing public service profile and uses the current agent display name, saved business photo (falling back to the owner's public avatar), and trusted tutor verification. The saved publisher flag does not grant a badge. Missing photos use the existing initials fallback.

A bookmark in the header replaces the large save button. Its persisted state is included in the original detail response, scoped to the signed-in viewer; save/removal is idempotent, ignores repeated taps while pending, preserves state on a failed response and cancels UI completion after leaving. Open/Buy stays in a safe-area footer outside the scroll content. Paid entitlements, billing readiness, Play distribution limits and booking access retain their existing routes and checks. Kira receives only the visible preview as an extract, never a claim that it has read the whole file.

The resource read remains one SQL query for tutor identity and bookmark state. It validates the identifier and campus, requires an active tutor in that campus, retains block visibility checks, returns only the public image projection and uses private/no-store caching. No migration is required; optional business details are read through to_jsonb for compatibility.

Orders replace the horizontal icon/connector strip with a status summary and expandable timeline of actual recorded events. Completed orders start compact; current orders expose their history immediately. Pickup and delivery labels remain distinct, and pending, failed, cancelled, refunded and disputed states do not acquire a delivered label. Fulfilment details are grouped with the summary. Items share one compact list, review actions are small rows, the optional review form names its selected item, and completed orders no longer show a handoff code. Amounts and fee calculations are unchanged.

Local validation: 1,157 Worker tests (including the PostgreSQL tutor-resource and listing-management integration checks), 400 app regression checks, 10 contracts tests, mobile/server/contracts type checks, portal lint/type check/production build, the mobile production web export, Worker deployment dry-run and regenerated mounted-route cache inventory. No production purchase, review, profile or listing was changed for validation.

The dedicated Resource and order phone UI workflow uses the full exported app with intercepted synthetic API responses. It checks 360px/390px layouts, the pinned action, bookmark persistence, review submission, order history, pending payments and dark mode, and retains screenshots as a CI artifact. Local screenshot execution is unavailable because the browser binary is absent and the installation network is blocked; The first CI run passed and its 360px/390px light, dark, expanded-timeline and pending-payment screenshots were inspected. The final pass shortens the resource header to fit 360px and captures bookmark interactions after their confirmation notification is dismissed. Browser evidence is not an Android device build.
