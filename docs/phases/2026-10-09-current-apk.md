# Current Android release: 0.3.24 / 54

The user requested all recent pending work in main, a current APK, and repairs to slow app screens. This release combines the community/native-push/admin/map changes, BACHS adapter and pricing foundations, durable Paystack replay protection, class-only daily mute and exam routing, live GPS recovery, keyboard corrections, and the Workers AI connection. BACHS checkout activation remains gated; no approved fee profile or live-money transaction was created by this release.

The shared mobile transport now preserves account-local read data through token renewal. Logout and account changes clear it. Mutation invalidation advances only affected resources, so a message read receipt cannot discard a pending GPA read. Resource generation tokens prevent an old, invalidated response from restoring stale cache data. Cached screen content is retained in bounded memory for five minutes and used only for rendering while a current read reconciles it. Checkout, payouts, and other mutations continue through the live API.

Today, feed, store, GPA, timetable, inbox, and conversation views retain usable content during refresh. GPA no longer waits for the grading catalogue, timetable no longer waits for exam periods, and message history no longer waits for its read receipt before appearing. New transport tests cover same-account renewal, account switching, scoped receipts, explicit stale rendering, and late-response races.

Six exact migrations were rehearsed or matched against existing rehearsal ledger hashes, then applied atomically to production before publishing the Worker. The alarm migration's malformed dollar quotes were corrected. Its fixture now uses explicit PostgreSQL aliases and UUID parameter casts. The dated production proof records source hashes, private grants, scoped POIs, preserved aggregate counts, and rolled-back replay fixtures. Worker, web-release verification, and APK workflows require this proof.

Validation: backend type check/build and 96 suites / 828 tests passed; contracts type check and 10 tests passed; 181 root regressions, three alarm-routing cases, and both GPS/map harnesses passed. Portal lint/type check and production build passed. Mobile type check and static production export passed. Physical-device screen timings and keyboard acceptance are still device checks, so automated results do not claim a measured latency for every screen.

The ARM64 APK builds the triggering main commit, embeds its build ID, requires the existing test signing certificate, and verifies its package, version, SDK, ABI, and checksum. Before upload it requires a successful matching Worker deployment, both Vercel production surfaces, current main, source manifests, and anonymous authentication boundaries. Deployment and package outcomes are recorded in their Actions runs and the APK build receipt.
