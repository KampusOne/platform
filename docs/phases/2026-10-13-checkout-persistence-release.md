# Android 0.3.28: durable checkout and screen tracking

An additional review of the 0.3.27 release found that changing quantities on the checkout screen could leave a failed encrypted cart write while still permitting a quote or order. Checkout now completes the owner-scoped, read-back-verified cart flush before either request and checks the account/campus revision again after that asynchronous boundary. A real storage failure remains visible, sends no quote/order request, keeps the selected quantities, and can be retried after storage recovers. The existing request lock and server quote/order idempotency remain in place.

The marketplace checkout route now participates in the existing analytics and first-party screen-visit streams. Only its allowlisted route name is recorded; no product, order or user value is added to telemetry.

Fourteen focused regressions pass, including quantity changes followed by failed persistence, failure immediately before order confirmation, successful recovery, both screen tracking streams, Buy now quantity preservation, two-column layouts, and native encrypted draft recovery. The mobile CI job now executes these tests from its installed mobile dependencies.

The new APK uses 0.3.28 / versionCode 58 because the preceding 0.3.27 artifact has already been built and published. It retains all merged draft, Kira/upload, messaging, marketplace and campus-reference corrections. A non-default-branch review build checks its package, signing identity, source and byte digest, and proves that its server/database/shared-package trees are identical to the successfully deployed main backend. It changes no production download pointer. Public publication through the existing release workflow still requires matching main/Worker/web receipts after merge. This follow-up adds no provider charge, finance-policy change, database migration or paid transaction. GST remains an approximate reported landmark; physical-device and signed-in live-provider acceptance cannot be inferred from source tests.
