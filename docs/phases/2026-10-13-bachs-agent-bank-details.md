# Bachs bank details and agent withdrawal release

Status: implemented for review; production rollout and Android 0.3.31 / build 61 are blocked on Bachs Connect activation and verified live transfer acceptance. No APK is released from this change. The latest request limits this pass to bank-name verification and dashboard bank editing, with the associated payout safeguards.

The live merchant-key probe returned supported Nigerian banks and successfully resolved the merchant's existing saved bank account name. The verified Bachs routes are GET `/v1/reference/banks?country=NG` and POST `/v1/misc/bank-accounts/resolve`; the routes shown in the supplied ChatGPT screenshots are not used. GET `/v1/accounts/me` reported payouts enabled and Connect absent from `enabled_capabilities`. General merchant payouts go to the merchant's own bank. Agent withdrawals require recipient-only Connect accounts and an approved bank destination belonging to each account. The code never substitutes Paystack for a Bachs request.

Agents open Bank from their dashboard, search supported banks, enter a 10-digit account number, confirm authorization, and see the name returned by Bachs before saving. A save rechecks the name server-side and creates an encrypted, campus- and owner-bound revision. API responses show only the account name, bank and masked suffix. Approved bank snapshots cannot be edited in place. Editing is blocked while a withdrawal reserves funds, but permitted after a verified failure restores those funds. Saved details can wait in PENDING_PROVIDER while Connect activation is pending. Identity and independent account ownership approval remain required; account-name lookup alone is not ownership proof.

Withdrawal commissions are graduated: 8% on the first ₦10,000, 6% on the next ₦40,000 and 5% thereafter, calculated once in integer kobo. The minimum is ₦2,000. Buyer product commission remains 2.5%. Quotes seal gross withdrawal, commission, bank amount, policy and recipient. The agent accepts the exact commission and bank amount. No active production withdrawal policy was silently created. New Bachs policies use PLATFORM fee bearing; existing Paystack receipts and policies retain their provider and historical economics.

Pending requests create an in-app notification and push-outbox record. Admins can inspect the profile, sales and available-earnings journal history, then approve with one checkbox and an optional note. Approval reserves a stable provider reference, confirms the exact connected bank recipient, transfers the sealed gross into its Bachs balance and pays the sealed bank net. NGN-to-NGN payouts do not use the FX quote API. Bachs' actual fee is platform expense; the remaining commission cash is returned to the platform. POST acknowledgements never establish payment. Independent GET evidence must match recipient, amount, currency, reference and environment before a paid journal or a failure refund commits. Lost acknowledgements reuse the same idempotency keys. Signed payout events trigger fresh verification; scheduled recovery is fairly queued and does not fabricate verification timestamps. Failed payouts restore the full withdrawal and book no commission. Actual provider failures and unmatched evidence remain visible.

The five migration sources were applied and registered in two atomic transactions on the existing isolated rehearsal branch. SQL commission results matched boundary examples; bank and payout functions exist; two active campus delivery zones were created by the previously prepared delivery recovery migration. The rehearsal is not a fresh current-production snapshot because the project branch quota is full. No production migration or real bank transfer was performed in this pass. See `database/verification/rehearsal-20261013-agent-banks.json` for exact source hashes and limits. APK workflows require a separate production agent-bank proof with Connect activation and a verified real agent payout; rehearsal evidence cannot satisfy it.

Validation includes bank-list and name lookup, encrypted storage and AAD isolation, campus/owner authorization, saved-bank revisions, payout locks, single-checkbox approval, pending provider capabilities, duplicate and lost responses, exact bank net, signed-event verification, failure restoration, commission recovery and append-only journals. The bank setup suite passes 18 tests; the finance suite passes 52 tests; the encrypted-envelope suite passes five cases. The full server run was followed by isolated retries for two test workers killed under simultaneous build memory pressure and the updated AI-stage response assertion. Final counts and build evidence are recorded in the pull request after verification completes.

Other already prepared release edits remain in the same branch. This phase does not certify unfinished community reply redesign, reaction latency, analytics charts, automatic checkout return UX, or 5,000 simultaneous real-provider sessions.
