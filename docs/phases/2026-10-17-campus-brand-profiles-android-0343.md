# Campus brand profiles and Android 0.3.43 / build 73

Tapping a photo or name in **Top campus brands** now opens that brand's vendor, tutor or rider profile. The brand rail no longer silently filters marketplace products. Search and product-category filters remain available, and the destination profile contains the brand's listings.

The rail and business profile use the existing KampusOne verification seal only when the API explicitly returns `verified: true`. Both endpoints derive verification from the trusted agent profile's `verified_at` value; public profile metadata cannot award the badge. Older responses without a verification field show no badge. The API retains campus scope, enabled/active brand checks and blocking in both directions. No database migration or financial changes are needed.

Android 0.3.43 advances the version code to 73 and includes all tutor/vendor listing, resource and order improvements prepared for 0.3.42. It uses uniquely named APK assets and the existing signing certificate. Package, source revision, ABI, signature, deployed backend and web publication receipt checks remain required. The APK preflight also runs the marketplace navigation regressions.

Checkout now sends `IN_APP` for the entire purchase, including the rider fare. The cash option and split cash/online explanation are removed. Quote and order entry points reject new cash requests before database side effects. Historical cash orders and their verified receipts, balances and settlement rules remain supported; no ledger mutation model or database migration changes.

The old delivery picker advertised only OSM/high-confidence or entrance-verified places, then truncated its UI to 20 entries. The replacement fetches every page of the university's published directory, including both campuses, aliases and campus names, and presents a compact field opening a searchable virtualized list. Published directory landmarks can be used as area points; a verified entrance takes precedence when present. Missing coordinates are never generated, draft/foreign campuses stay hidden, actual mapped roads are still required, and approximate entrance access is disclosed with the fare. Vendor pickup settings offer the same published mapped landmarks.

The catalogue returns a pickup-readiness boolean derived from a saved published map point or a recent accurate seller position, without returning the private GPS coordinates. Checkout only offers rider delivery when every seller is ready. Otherwise it selects the available pickup option and explains rider unavailability beside fulfilment choices. If a pickup position expires while checkout is open, the server returns a structured reason and the client returns to pickup before another quote.

The React review confirmed one accessible profile action per brand, explicit badge state, a nonshrinking seal next to wrapping names, and no extra per-brand requests.

The phone workflow checks the exported app at 360px and 390px, including an actual tap at the avatar position and a tap on the name, correct destination ID, and badges in the rail and profile. It also checks rider-ready versus missing-pickup checkout, online-only payloads, location search beyond the first page, and the retained resource/order layout, dark mode, bookmarking, pinned action, timeline and review checks. The synthetic auth fixture includes both access and refresh expiry values so protected tab screens are exercised in a complete local session. Screenshot evidence is uploaded as `resource-order-phone-ui`; its final result and the signed APK publication must be verified before delivery.
