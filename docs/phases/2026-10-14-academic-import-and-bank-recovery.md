# Android 0.3.32: academic imports and bank management

Production evidence linked the photo timetable failure to `AI_TIMEOUT`. The image path previously waited for separate OCR before calling vision inside a 45-second cap. Timetable, calendar and exam requests now use a 90-second inference budget, a shared 150-second document-processing deadline, and a 180-second mobile request limit. Native Gemma reads the private original image directly, without waiting for OCR. Schedule extraction disables extended thinking and requests JSON. Dated exams receive their dated schema without contradictory weekly-class instructions. Scanned PDF transcription also disables extended thinking. The text/PDF extractor now matches the existing 16 MB private-reader limit instead of incorrectly rejecting valid 8–16 MB documents.

The existing owner-bound request record supports at most two retries for classified service failures, under the same request and import allowance. Completed requests replay their saved result; pending requests are checked, not duplicated. Retry claims are atomic and rate limited. A fresh processing timestamp prevents an older failed attempt from being declared stale during its retry. Mobile checks the saved result after a lost response. Quota, ownership, file-size and validation failures remain visible. Import review and explicit saving are retained.

The recurring screen failures were recorded as `UI_RANGEERROR_DATE`. Purchase rows contain PostgreSQL timestamps with spaces, microsecond fractions and short timezone offsets. Purchases passed them directly to `Intl.DateTimeFormat`; Android cannot reliably parse that grammar. A shared normalizer now produces ISO timestamps before purchase display and completion-time checks. Invalid timestamps display an explicit unavailable date. The Android runtime smoke also exercises the recorded timestamp grammar.

The bank screen shows one saved-account card, a readable approval state, and Edit/Delete actions. The entry form opens for adding or editing. Deletion uses an authenticated, campus- and owner-bound endpoint and the same profile lock as withdrawals. It disables the active destination and clears application payout fields while preserving sealed historical destinations and financial receipts. Pending withdrawals and bank verifications block removal. Repeated deletion is safe; a stale delete cannot clear a replacement. The payout activation switch remains disabled as established for the preceding release.

Validation covers all three photo-import routes and persisted previews, provider deadlines beyond the former cutoff, alternate-provider time reservation, bounded retry and quota reuse, loss-of-response recovery, owner/campus isolation, bank removal and payout locks, and Android-compatible purchase timestamps. The live protected provider probe exercises the actual extraction adapter for printed photos, handwriting, PDFs, academic calendar text and exam text. Synthetic fixtures do not establish accuracy across every real-world document or handwriting sample.

Provider configuration follows Cloudflare's native Gemma example: https://developers.cloudflare.com/workers-ai/get-started/workers-wrangler/.
