# Map GPS recovery and Android 0.3.22

Selecting My current location and Back Gate could leave the map showing a blue approximate dot, no route, and a generic request to retry. The previous location hook awaited cache and a one-shot high-accuracy request before registering the live watcher. A stalled native request therefore prevented better GPS measurements from reaching the map. Movement-filtered updates also allowed a stationary phone's previously good fix to expire.

The watcher now starts independently of both optional requests. Initial acquisition is bounded to 12 seconds; watching continues after that deadline, so a later qualifying live fix restores route readiness automatically. The existing 50-metre accuracy and 60-second freshness requirements are retained. A delayed cache, older one-shot result, or inaccurate reading cannot replace a recent good live fix. Retry, focus changes and app backgrounding invalidate obsolete requests and remove late subscriptions. Stationary Android updates use a zero movement filter; the map also refreshes a fix that expires without a new reading.

The directions drawer distinguishes location acquisition from route calculation. Failure copy identifies approximate location, disabled device location, or missing/approximate app permission. Settings and Choose starting point actions remain available without clearing the chosen destination. Returning from Settings rechecks permission and starts a new subscription. An old locate request cannot pan the camera after the user chooses a manual origin, changes campuses or clears directions.

`mobile/scripts/check-campus-location.cjs` executes the production hook with controlled native promises, sensor callbacks and a clock. It covers hung cache/one-shot requests, a timed-out request followed by automatic live recovery, stationary updates, accuracy/freshness, cache and sensor ordering, overlapping permission requests, blur/refocus cleanup, approximate/denied permission and returning from device settings. CI and the APK workflow run this suite together with the sourced map/viewer regression checks.

Android 0.3.22 uses version code 52 and builds the triggering commit, including the latest main-branch push-registration fix. The direct ARM64 build verifies package identity, source receipt, SDK, SHA-256 and the existing 0.3.20/0.3.21 test signing certificate so it can update the installed APK. No database migration or public landing-page change is required.

Automated sensor simulations and package verification do not establish physical-device acceptance. The remaining device check is to select current location and Back Gate, verify the route after a good fix, leave the phone stationary for more than a minute, change location permission in Settings, and return to confirm recovery. If the device genuinely cannot obtain a fresh fix within 50 metres, the app reports the cause and permits a manual starting point instead of inventing a location.
