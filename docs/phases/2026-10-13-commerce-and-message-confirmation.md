# Android 0.3.29: checkout configuration and confirmations

The reported upload and checkout failures came from an empty production `commerce_fee_policies` table. Product creation now remains available when its optional price preview is unavailable, while retaining normal category, photo, description, price, stock and encrypted-draft validation. An unavailable preview remains visible with a compact refresh icon. A scoped, audited operation restores UNIBEN's store policy using the user's requested 2.5% product commission: one buyer markup, zero additional seller commission, and the existing approved generic local collection profile. The operation records the previous policy, publishes a new immutable version, runs atomically, and is idempotent. It changes neither processor rates nor past orders.

Kira's raw Neon/Drizzle result used a PostgreSQL expiry such as `2026-10-13 14:52:47.080544+00`. That wire format is not portable to Hermes. Some saved policies also use the valid `MERCHANT_ABSORBS` mode that the app's validator omitted. A rehearsal using the actual driver reproduced the rejected Pro quote; after normalizing API timestamps and accepting this mode, the same response contract was accepted at its unchanged 600000-kobo total. Kira offer dates, subscription end dates, pending checkout dates and store quote expiries now use ISO 8601. Strict integer-amount, identity, tier, expiry and provider-amount checks remain in place.

The three messages shown in the screenshots were already present in the production database with their notices and outbox entries. New message writes, thread updates, notices and push enqueueing now commit together in one SQL statement. This removes two serial database round trips after message insertion and prevents a downstream notification failure from leaving a secretly committed message behind a failed response. A concurrent retry that loses the initial lookup race reads and confirms the same exact intent. A delayed initial response also triggers a fresh authorized thread read; acknowledgement requires the same sender, text and reply target. Existing owner-scoped encrypted outbox, request IDs, bounded retries and session checks remain intact.

The reported upload, checkout, Kira and message recovery controls use accessible 44-pixel refresh icons with disabled/busy states. Pending message feedback is compact and appears after the initial send, rather than occupying another large card. Android 0.3.29 / versionCode 59 retains the preceding checkout-persistence, two-column marketplace, map and draft fixes and the established signing identity. Existing deployment/source/signature publication guards are unchanged.

Validation: 906 backend tests across 113 files; 74 focused client, draft, message-recovery, keyboard, checkout and release regressions; mobile/server/portal type checks; server and portal builds; portal lint; mobile web export. The new message/timestamp tests cover atomic rollback, lost-response replay, concurrent retries, foreign identities and raw database dates. The pricing operation was applied twice on `experience-release-rehearsal-20261003`, yielding one immutable policy and one active pointer. No live payment was initiated. Final CI/deployment receipts and the signed APK receipt are recorded by the release workflows. Physical-device and charged-provider acceptance cannot be inferred from these checks.
