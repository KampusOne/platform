# Tutor and vendor listing actions

Tutor materials and sessions now use the seller listing layout: a 72px cover or file-type placeholder, a two-line title, publication status, price, and a trailing three-dot menu. The large View material/View bookings/Manage tutorial buttons are removed. Tapping a material opens its preview; session management remains available from the session row and menu. Vendor gallery covers and their existing edit/archive actions are preserved. Deletion is explicitly styled and requires confirmation.

The owner dashboard now returns material cover URLs, subjects and exact text revisions. The new tutor editor changes material title, description, course code, subject, access, price and cover, or session title, description, course code, format, capacity, location, price and cancellation cutoff. Existing uploaded files, playlists, publication states and purchase/booking amounts remain intact. A changed course code clears its old course association.

Material and session updates verify current campus, ownership, active tutor role, allowed publication state and the loaded revision. Changed covers must reference the owner's campus image upload; URLs with the upload cache query are supported. Submitted content cannot bypass review through this editor. Soft deletion is retry-safe and retains referenced records. No database migration is required; this uses the existing campus-release cover/subject columns.

Edit drafts use the encrypted owner-scoped listing namespace and a separate per-record key. A failed draft restore or listing read cannot autosave a blank replacement. Stale edits require an explicit reload. Interrupted mutation responses are checked with a fresh authorized list read; failed deletion keeps the row, and a delayed pre-deletion read cannot restore a removed row.

Validation: 1,152 Worker tests including the six new PostgreSQL API checks, the full root app regression suite, ten contracts tests, app/server/contracts type checks, mobile production web export, portal lint/type check/production build, the Worker deployment dry-run and the regenerated route-cache inventory. The new interaction tests run in mobile CI. Automated interaction tests are not Android device visual verification; local screenshot execution was unavailable because the Chromium download failed. No production listing was edited or deleted during verification.
