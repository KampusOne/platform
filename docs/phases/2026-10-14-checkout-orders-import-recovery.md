# Checkout, paid agent orders and image import recovery

- Checkout normalizes local Nigerian mobile numbers to +234 on both the client and Worker. Missing recipient details are checked before quote creation, with inline errors, a visible border and scrolling to the first invalid input. API validation supplies field messages and no longer promises nonexistent highlights.
- Agent store lists, direct order details, dashboard counts/activity, legacy earnings summaries and rider delivery/route reads only include PAID, ACCEPTED, READY, IN_DELIVERY and DELIVERED orders. Buyer/admin history and ledger-derived balances are retained. The mobile store-order view also filters older cached responses.
- Optional pixel border detection no longer rejects supported source images. If cell isolation is unavailable, focused original-image reads assemble every selected weekday and use the existing strict coverage, level, time-header and contiguous-cell validation. Layout reads use a bounded token/time budget; all reads retain the original request reservation and deadline.
- Live release checks cover the 19 printed 100-level classes, 20 printed 200-level classes and a privately decoded WebP version, alongside handwriting, calendar PDF and exam text.
- Layout panels split only at detected day borders, retaining every day's complete level labels. Pixel-derived column/row counts reject an omitted inventory before transcription and permit one bounded internal inventory reread. Private WebP pixels are decoded with a bundled, dimension-guarded WASM codec into a lossless representation for the same position checks. The original stored file is retained. Cell panels omit excess blank image width; the live probe serializes dense-grid cases to bound peak memory.
- Metro explicitly watches the pure shared commerce helpers, including clean mobile-only CI installations. The mounted cache-route manifest has been regenerated for the changed routes.
- Cell transcription maps each label to its visible panel number. A malformed panel inventory receives at most one internal reread under the original deadline; missing keys, uncertain pixels or a mismatched level cannot be silently shifted into valid cells.
- Pure image processing runs in a private Node function on the existing Vercel portal, avoiding Cloudflare Free CPU limits. Sixty-second Ed25519 service tokens bind each request to its exact body; the domain-separated signing key remains in the Worker. Only public verification material is published. The helper has no database access, user authorization or AI/provider credentials, and stores no files. Worker ownership checks, quotas, full-week validation and the original 150-second import deadline remain authoritative. Pixel logic is shared, and WebP uses a bounded native decoder in the Node helper. No plan upgrade or paid CPU setting is enabled.

Regression coverage includes invalid/local phone numbers, visible client/server field messages, actual PostgreSQL-backed agent list/detail/dashboard reads, selected-level cell geometry and recovery that rejects partial rows, mixed levels and contradictory headers. Android release 0.3.34 uses version code 64 and the existing signing identity. CI/live checks and source-matched release receipts remain publication requirements.

No database migration is needed. This is a read policy and validation change; finance rows, provider receipts, admin order access and quota accounting are not rewritten. Model accuracy is checked against fixture course/day/hour tuples; arbitrary unreadable documents still fail visibly without a partial import.
