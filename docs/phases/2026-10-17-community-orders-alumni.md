# Orders, communities, Alumni recognition and foreground notifications — Android 0.3.40 / build 70

Order details now show a compact status tracker, seller and total summary, real product thumbnails, pickup/delivery details, payment breakdown and readable activity labels with the latest event first. Initial loading no longer starts the pull-to-refresh spinner. Existing payment, delivery-code and optional product-review rules remain authoritative.

Community profiles have a shorter cover, overlapping square avatar, clearer subscription controls and a flatter post list. Unsubscribing requires a deliberate confirmation. Comments open a dedicated conversation view with the same avatar, name, timestamp and attachment treatment as the feed. Community replies use the actual shared feed composer, including account-scoped draft retention, keyboard handling and photo uploads. Optional request IDs prevent retrying a comment from creating duplicates; older clients can continue submitting without them.

Admins with scoped `users.verify` access can select no badge, standard KampusOne recognition or a purple Alumni badge from the existing user-detail controls. Badge assignment and removal are audited atomically and compare both the previous assignment and badge kind. Recognition never changes KYC, enrolment, restrictions or roles. The type travels through profiles, feeds, quoted posts, replies, discovery and community responses. The database constraint accepts STANDARD and ALUMNI only; no accounts were automatically assigned Alumni status.

Sent and received messages share one physical left-swipe threshold, horizontal-gesture checks, right-side reply cue, reduced-motion reset and an explicit screen-reader reply action. Rightward and vertical swipes do not trigger replies.

Foreground notices use a themed glass banner, a person's profile image for actor notifications and a system icon otherwise. Android 31+ uses the installed optimized blur implementation, with its built-in translucent fallback on older Android versions. Native banners are suppressed while the custom foreground banner is visible; native sound and background notifications remain enabled. Live inbox events also produce in-app banners, including when push is unavailable. Initial history is seeded quietly, delivery IDs deduplicate native/live arrivals and changing account or university clears notices. Post favourites now notify their author once and respect the existing likes push preference.

It adds only a constrained recognition column and an optional community-comment replay key/index.
