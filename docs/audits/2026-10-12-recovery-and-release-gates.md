## Security, legal and rollback

The storage ADR is `docs/architecture/2026-10-12-private-snapshots-and-live-updates.md`. Native records use authenticated AES-GCM and SecureStore key custody. Web private records are session memory only. Media bytes remain in the OS app sandbox; metadata is encrypted. This is not end-to-end encryption or a complete offline database replica. Cold offline login is not granted from editable cached role/profile data. Listing, onboarding, class/calendar/exam imports, campus activities, Kira, publishing and private-answer drafts now use bounded strict recovery and verified native autosave. Saved personal-date copies reject malformed/unreadable data as a whole; server confirmation and device-copy failure are distinct. Transient editor/business-profile fields, edited legacy pending-date conflicts and physical storage-pressure acceptance remain open. Web forms explicitly describe session-only retention. Optional telemetry is encrypted, expires after 48h and remains disposable; unscoped legacy plaintext metrics are discarded, not migrated as primary work.

Unsubmitted primary records do not silently expire as disposable caches. Quotas protect existing drafts and reject new work when full. Owner/tenant changes, session epochs, logout key deletion and file cleanup are checked in synthetic tests. Device sharing, OS backup/keychain reinstall, SecureStore failures and screenshots still need independent/native review.

No financial ledger logic was changed to manufacture success. Existing append-only balanced record semantics remain authoritative. A cart, browser redirect, upload100%, cached entitlement or pending message is not a server-confirmed payment/delivery/save.

Privacy and Terms remain visibly DRAFT. The exact entity/contact/retention/processors/minor/refund/renewal/effective-date decisions and qualified Nigerian legal approval are required by the supplied master prompt and `docs/legal/2026-10-12-publication-checklist.md`.

Rollback uses ordinary source revert commits, preserving concurrent work. No production DB migration needs rollback.
