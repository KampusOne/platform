# AI activation and verification — 24 September 2026

## Implemented routing

Study questions, summaries, revision notes and practice quizzes use Gemini. Timetable text and JPEG/PNG/WebP photos use Hugging Face's chat-completions router with distinct configured text/vision models. PDF timetable input explicitly uses Gemini, which accepts inline PDF documents. The timetable screen discloses that distinction before submission. There is no automatic provider fallback, automatic provider retry, purchase, subscription change or billing activation.

A provider key is not proof that a model is hosted, supports the supplied input or has usable credits. Model IDs stay configuration-driven. `/v1/ai/status` reports configuration presence, not a successful live inference test.

## Worker configuration

The target is Cloudflare Worker `platformp`. Existing `GEMINI_API_KEY` and `GEMINI_MODEL` remain in use. Do not copy keys into Expo, Vercel public variables, source control or chat. The only new provider settings are in `server/.ai.env.example`: secret `HF_TOKEN`, plain-text `HF_CHAT_MODEL` and `HF_VISION_MODEL`. The Hugging Face token needs Inference Providers permission. Use exact currently hosted model IDs and verify vision support separately.

Production's tracked `AI_ASSISTANT_ENABLED` is now true; missing keys/model settings still fail closed. Staging stays disabled. `keep_vars: true` preserves dashboard variables not declared by the repository, including model selection and quota overrides. Secrets remain separate. No existing database, auth, storage, email or payment keys need replacing. No database migration is needed: the integration uses the existing private `app_private.ai_requests` table.

Defaults remain 5 attempts per user and 100 globally per WAT calendar day. Existing `AI_DAILY_USER_LIMIT` and `AI_DAILY_GLOBAL_LIMIT` overrides are respected. Zero or invalid non-empty values block new reservations; zero is not converted back to the default. Reset is midnight Africa/Lagos. These are technical safety limits, not a new commercial entitlement or an unlimited/free-year offer.

Application request caps are not a provider billing guarantee. Use accounts with billing disabled or provider-side hard spending restrictions appropriate to the approved budget. No paid inference account, new payment method or paid top-up was enabled by this code change.

## Request, retention and privacy behaviour

A separate advisory-lock statement and quota/idempotency insert run in one Neon READ COMMITTED transaction. Counts are evaluated after waiting for the lock, with a consistent database-time WAT day. User/global checks and the unique request claim commit together before provider I/O. The lock is not held during inference. Concurrent duplicate requests cannot claim two slots. Configuration/file validation failures and rejected reservations do not spend allowance. A reserved provider attempt counts even on provider failure; provider retries are never automatic. Replaying the same key reads the completed result or processing state without another call. A client timeout reuses the existing key instead of creating a duplicate attempt.

The server checks attachment ownership, resource kind, MIME type, stored and actual size (8 MiB maximum). Plain UTF-8 text is supported by the server; the existing app picker offers images/PDFs. Text/context is bounded to 60 KB, at most six recent turns, and output to 4,096 tokens. This does not independently count PDF pages or guarantee an exact token/currency cost. A larger source must be split; the adapter does not silently truncate an incomplete provider answer.

Completed study outputs are saved with prompt, source ID/name and thread reference. History is owner-scoped, searchable and paginated. Follow-up context is fetched only from that owner. New version-2 result content has a 90-day retention policy enforced by read boundaries and the existing maintenance cron. Deleting one saved answer removes that row's content; related answers remain. A content-free tombstone remains until the daily allowance is safely past (at most two days from creation), preventing deletion from resetting the quota. Existing uploaded source files use the separate media retention policy and are not deleted with an answer. No signed source URL is persisted in the draft cache.

Timetable extraction produces a preview, never direct calendar writes. Invalid/ambiguous rows are omitted with warnings; the user can add and edit classes manually. Class title, weekday and ordered 24-hour times are validated before save. Existing reviewed import and alarm APIs remain in use; successful timetable persistence is distinct from device notification permission/delivery.

## Required live acceptance checks

After deployment, sign into the app and open Study space. Configuration should show no missing Gemini variables. Ask a small academic question, summarise a short PDF, create notes and practice questions, then reopen each result from Saved work. Refresh during one in-progress attempt and retry with the same key: it must not consume an additional reservation. Search history and verify another account cannot read/delete the item or reference the source.

Configure and test HF text and vision models using (1) a short pasted timetable, (2) a clear real university timetable photo, (3) an ambiguous/unreadable photo, and (4) the same schedule as a PDF through the explicitly disclosed Gemini path. Compare every extracted field with the source. Nothing should be saved until confirmation. Confirm the saved timetable and eligible device reminders separately.

The standalone provider regression suite uses mocked provider responses and runs with `node --experimental-strip-types --test tests/ai-provider.test.mjs`. Server route regressions cover auth, ownership, history deletion, quota rejection, claim/replay ordering, safe failures and timetable validation under `npm test`. Repository CI performs full server/mobile typechecks and builds. Neither mocks nor a green build prove that a live provider key/model/credit balance works. No live model-quality or physical-device acceptance result should be claimed without performing these checks.

## Rollback

Set `AI_DAILY_GLOBAL_LIMIT=0` on the Worker to immediately reject all new claims while preserving cached answers and saved history. This variable is not overridden by the tracked configuration. For a full feature pause, change `AI_ASSISTANT_ENABLED` to false in both the dashboard and the tracked production configuration; otherwise a later deployment can restore the tracked true value. Do not delete the private request table, existing results or source files to roll back the feature.
