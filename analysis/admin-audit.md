## Permission and scope design

`/v1/admin/access` is authoritative. The browser never authorizes from user-editable metadata. A finance-only staff member sees finance and analytics capabilities when those specific grants exist; no users, identity documents or unrelated staff workspaces are linked. Direct requests remain independently authorized by Worker middleware and resource checks implemented by the backend agent.

A global operator can choose all universities or one institution. A restricted operator selects a concrete authorized university; the UI does not label a single scoped query as an all-university aggregate. Scope affects request URLs and cache/result keys. Sensitive detail panels are invalidated on institution change. Admin context remounts when account identity changes. Saved navigation/filter preferences contain no account records, documents, bank details or auth tokens.

Staff editor requires a reason and a concrete review before applying grants. Public badge, publisher capability, identity/document review, agent approval and payout ownership are distinct forms/permissions. Finance-only staff are not offered arbitrary user export or identity-document access. No bulk export feature is advertised as implemented.
